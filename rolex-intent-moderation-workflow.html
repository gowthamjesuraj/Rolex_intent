MAIN ARCHITECTURAL ISSUE
Multiple generations of architecture coexist in the same environment: English still runs the older inbound → spam → AI intent → intermediate → main-topic model, while French was rebuilt in 2025 into a direct intent → moderation-hybrid path.
MAIN OPPORTUNITY
Standardize classification across languages and normalize intent once, so the same downstream logic can serve every language instead of two parallel designs.
CURRENT VS. RECOMMENDED

One architecture, not two

The recommended direction: one classification architecture → one normalized intent → one moderation action engine → an explicit fallback for anything the model can't classify.

CURRENT STATE — TWO GENERATIONS

1EN: Inbound → Spam check → AI intent
2EN: Intermediate routing → General Comment correction
3EN: Main Topic tagging → Trigger Moderation V3
4FR: 2025 AI intent → Moderation Hybrid
5FR: Internal Moderation Hybrid → Trigger Moderation V3

RECOMMENDED FUTURE STATE

1Eligibility → Spam / quality → Language routing
2EN / FR AI model → one normalized intent
3General Comment? → context check → Main Topic
4Action decision → Hide / Escalate / NRR
5Unclassified → fallback queue → human review
MANAGEMENT TAKEAWAY
The rule engine today is a mixture of active EN/FR processing and legacy disabled configurations. The biggest improvement is to standardize classification, normalize the intent once, separate classification from moderation actions, and explicitly capture unclassified messages rather than letting them fall through the workflow.
